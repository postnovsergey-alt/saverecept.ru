# Самобранка

Личная книга рецептов. Кидаешь ссылку — рецепт сам разбирается на состав и шаги,
получает сжатую фотографию и уезжает на нужную полку. Работает и с сайта, и из
Telegram; у каждого пользователя своя книга.

Вход по email и паролю (регистрация на `/register`, открытая). Telegram-бот
привязывается к аккаунту через одноразовый код на странице «Профиль» —
после привязки рецепты из бота падают в книгу этого пользователя.

**Пошаговая инструкция по установке через VS Code — в [VSCODE.md](VSCODE.md).**
Ниже — справка по устройству.

## Запуск

```bash
./setup.sh              # локально: зависимости, тесты, конфиг, примеры, сайт
./setup.sh --remote     # на сервер по SSH: копирование, проверки, деплой
./setup.sh --update     # обновить уже развёрнутое
```

Спрашивает только ключ Gemini, токен бота и домен — один раз, дальше помнит.
Всё остальное (пароли, порты, конфиги, проверки, откат) делает само.
В VS Code это одна кнопка `Ctrl+Shift+B`, см. [VSCODE.md](VSCODE.md).

Отдельные шаги, если нужен ручной контроль:

```bash
./deploy/inspect.sh          # обследовать машину, ничего не трогая
./deploy/deploy.sh --dry-run # только проверки
./deploy/rollback.sh         # вернуть как было
```

Что делают проверки:

- **Ресурсы.** Свободная память (сборка образа просит около 900 МБ), диск,
  текущая загрузка, наличие свопа. Если памяти мало — деплой останавливается,
  чтобы сборка не спровоцировала OOM killer на чужом процессе.
- **Порт.** Занятый соседом порт определяется и предлагается свободный.
  Контейнер слушает только `127.0.0.1` — наружу трафик пускает ваш nginx.
- **Соседи.** До деплоя снимается состояние всех чужих контейнеров, активных
  systemd-сервисов и слушающих портов. После — сверяется. Если у соседа что-то
  перезапустилось, упало или перестало слушать порт, скрипт это покажет и
  предложит откат.
- **Откат.** Предыдущий образ помечается тегом, папка `data` архивируется
  (хранятся пять последних копий). При неудачном старте откат происходит сам.

Соседей скрипты только читают. Останавливать, перезапускать и менять чужие
контейнеры они не умеют по построению.

Потребление в работе: сайт 120–180 МБ, бот около 60 МБ. В `docker-compose.yml`
выставлены жёсткие лимиты 512 и 384 МБ, чтобы аппетит не мог вырасти.

## Проверка

```bash
python -m tests.test_parser   # разбор страниц, категории, ингредиенты
python -m tests.test_web      # страницы сайта, сжатие картинок, дедупликация
python -m tools.check_llm     # отвечает ли модель
```

Тесты работают офлайн — страницы лежат в `tests/fixtures`.

## Что где лежит

```
app/
  parser/
    fetch.py        загрузка страницы
    extract.py      три способа разбора: JSON-LD, микроразметка, эвристика
    llm.py          разбор моделью, с запасным провайдером
    classify.py     раскладка по категориям
    ingredients.py  «Куриное филе — 500 г» -> название + 500 + г
    images.py       скачивание, ресайз, WebP, миниатюры
    pipeline.py     ссылка -> готовый рецепт
  service.py        общий слой работы с базой для сайта и бота
  main.py           сайт (FastAPI, серверный рендеринг)
  templates/        Jinja-шаблоны
  static/style.css  всё оформление, один файл
bot/main.py         Telegram-бот
deploy/             скрипты безопасного деплоя
tools/              demo_seed.py, check_llm.py
```

## Как разбирается страница

По очереди, до первого осмысленного результата:

1. **schema.org в JSON-LD.** Так размечено большинство кулинарных сайтов,
   включая русские. Состав, шаги, время, порции и фотографии приходят готовыми.
2. **Микроразметка `itemprop`.** Та же схема в старом виде.
3. **LLM.** Включается, если задан `LLM_API_KEY`.
4. **Эвристика по вёрстке.** Заголовки «Ингредиенты» и «Приготовление»,
   списки под ними. Комментарии и реклама отсеиваются.

Ссылка на источник сохраняется всегда, повторное добавление той же страницы
дубля не создаёт: utm-хвосты и якоря при сравнении отбрасываются.

## LLM

Основной провайдер — Gemini через OpenAI-совместимый эндпоинт. Бесплатный тариф
на июль 2026: 10 запросов в минуту, 1500 в день, контекст 1M токенов — страница
рецепта влезает целиком с огромным запасом.

Важно: как только на проекте Google включается биллинг, бесплатный тариф на нём
исчезает полностью. Заводите отдельный проект и биллинг там не трогайте.

Запасной провайдер (`LLM_FALLBACK_*`) подхватывается автоматически, если основной
ответил ошибкой или упёрся в лимит. Подойдёт любой OpenAI-совместимый: OpenRouter,
DeepSeek, локальная Ollama.

Идентификаторы моделей у Google меняются. Посмотреть актуальные:

```bash
python -m tools.check_llm --list
```

Без ключа сервис работает — просто страницы без разметки разбираются хуже.

## Картинки

Оригиналы не хранятся. Каждая картинка приводится к WebP шириной до 1280
пикселей плюс миниатюра на 480 — её показывает библиотека. Фотография с
кулинарного сайта обычно весит 1–3 МБ, после обработки остаётся 60–150 КБ.
Одинаковые картинки дедуплицируются по хэшу содержимого, иконки и логотипы
мельче 200 пикселей отбрасываются.

## Категории

Правиловый классификатор по русским корням: супы, салаты, горячее, гарниры,
выпечка, десерты, закуски, завтраки, напитки, соусы, заготовки. Мгновенно и
бесплатно. При равном счёте выигрывает слово, стоящее в названии раньше —
поэтому «Суп-пюре из тыквы» уходит в супы, а «Картофельное пюре» в гарниры.

Подсказка от LLM добавляется к счёту, но не перебивает уверенные правила.
Категорию можно поправить на странице рецепта; поправленная вручную больше не
переопределяется. Список категорий и ключевых слов — в `app/categories.py`.

## Telegram

1. Токен у [@BotFather](https://t.me/BotFather) → `TELEGRAM_BOT_TOKEN`.
2. `python -m bot.main` (в docker compose поднимается сам).
3. Каждый пользователь в разделе «Профиль» на сайте берёт свой одноразовый код
   и отправляет боту: `/start КОД`. После этого бот пишет в его книгу.

Бот понимает пересланную ссылку, `/find творог`, `/last` и `/unlink`. Всё, что
он сохраняет, сразу видно на сайте: база одна, отдельной синхронизации нет.

## Кнопка «Поделиться» на Android

В манифесте объявлен `share_target`. Откройте сайт в Chrome на Android и
добавьте на главный экран — «Самобранка» появится в системном меню «Поделиться»
рядом с Telegram. Добавление рецепта с телефона превращается в два тапа прямо
со страницы рецепта.

На iOS Web Share Target не поддерживается — там остаётся бот.

## Оформление и скорость

Тёмная тема: фотография еды на тёмном фоне светится сама, поэтому интерфейс
уходит в тень и не спорит со снимками. Карточка — фото во всю площадь с
градиентной подложкой под текст; у рецептов без фото вместо неё нарисованная
заглушка в цвете категории.

Всё оформление — один CSS-файл, без веб-шрифтов и библиотек. Тяжёлых эффектов
вроде `backdrop-filter` нет намеренно: они дорого стоят на телефонах. Движение
только через `transform` и `opacity`, и полностью отключается при
`prefers-reduced-motion`.

Страницы собираются на сервере. JavaScript живёт только на добавлении рецепта и
галочках в списке продуктов. Картинки отдаются в WebP с `loading="lazy"` и
заранее известными размерами, поэтому вёрстка не прыгает. Service worker кэширует
картинки и статику.

## Что дальше

Модель данных готова к планировщику меню: у ингредиента отдельно хранятся
количество, единица и нормализованное название (`name_norm`). Это то поле, по
которому потом схлопнутся «куриное филе» и «грудка куриная» при сборке списка
покупок. Для меню понадобится справочник продуктов с КБЖУ и фасовками — сами
рецепты уже лежат в подходящем виде.
